OpenClaw Webinar Runbook

A screenshare-friendly code-along for local-only workflows. Terminal on one side, web UI on the other. The story arc: data intake review → operational memory → offline communications triage.

Local folder only No live integrations Enterprise-safe framing Reviewable markdown artifacts

1) Opening framing

~4 min

What to say

  • "We’re staying entirely local today: local folders, local files, no live system connections."
  • "I want to show useful patterns that survive enterprise security review and fit inside a short code-along."
  • "The outputs are markdown artifacts you can inspect, edit, and version."
Presenter note: Keep the trust story up front. You want the audience relaxed before you show any automation.

Screen setup

LeftRight
TerminalOpenClaw web UI
Folder contents, commands, outputsPrompts, agent reasoning, artifact generation
Optional line: "I’m using the web UI so you can see the conversational side, but the work itself is just happening against local files."

2) Quick product model: soul, heartbeat, cron

~5 min

Soul

Explain that the agent can be shaped with workspace guidance and behavioral preferences, not just one-off prompts.

Heartbeat

Explain that proactive behavior requires wake-ups. No heartbeat means no passive observation loop.

Cron

Explain that scheduled tasks are cleaner than persistent observation when you only need periodic artifacts.

Important: teach the concept, but don’t let scheduler mechanics take over the demo. The artifacts are the star.
Suggested line:
"OpenClaw can be passive, proactive, or scheduled. For today, I want you to notice the pattern: files go in, reviewable artifacts come out."

3) Demo one: Data intake review

~10 min

Tagline: Turn unknown files into a trustworthy intake report.

Prep

  • Folder: demo/data-intake/incoming/
  • Seed 3–5 files with structural issues, not toy data
  • Output target: demo/data-intake/reports/intake-review.md

Terminal actions

ls demo/data-intake/incoming
# optionally: open or cat one file briefly

Prompt

Review the dropped data files and create a markdown intake report with schema fingerprint, sanity flags, draft data dictionary, and questions to ask before use.

Your job is flagging and documenting, not cleansing.
Do not modify source files.
Do not make statistical claims beyond what can be directly observed.
Do not recommend value-altering fixes.

What to point out

  • Non-destructive review
  • Observed structure, not invented certainty
  • Questions before use are often as valuable as findings
Strong line: "This is a first-pass data reviewer, not an ETL pipeline."

Expected output sections

  • Files reviewed
  • Schema fingerprint
  • Sanity flags
  • Draft data dictionary
  • Questions before use
  • Recommended next checks

4) Transition: passive vs proactive

~3 min

After demo one, pivot into why file-based automation doesn’t magically happen unless you define when the agent wakes or runs.

Suggested line:
"If I drop a file in a folder and nothing happens, that’s not a bug — it’s a boundary. The agent needs a wake-up model."
  • Heartbeat = passive observation cadence
  • Cron = explicit schedule for repeatable jobs
  • For token-sensitive workflows, use cron when observation is unnecessary
Demo tip: don’t literally wait around. Show the config, explain the behavior, then move to the resulting artifact.

5) Demo two: Operational memory

~11 min

Tagline: Turn work residue into daily and weekly momentum docs.

Prep

  • Folder: demo/ops-memory/inbox/
  • Seed notes: standups, TODOs, release snippets, rough status updates
  • Outputs: daily-log-YYYY-MM-DD.md, weekly-hype-YYYY-WW.md

Terminal actions

ls demo/ops-memory/inbox
# optionally show a tiny heartbeat or cron example
# but keep the focus on the generated docs

Daily prompt

Review the notes in this folder and generate today’s operational memory log.
Summarize progress, blockers, notable decisions, and likely next steps.
Keep it concise, grounded, and useful to a manager.
Do not invent work that is not supported by the files.

Weekly prompt

Generate a weekly hype doc from this folder: wins, momentum, risks, blockers, and next bets.
Make it polished but not exaggerated.
Keep the tone crisp and upbeat while staying evidence-based.

What to emphasize

  • This is continuity, not just summarization
  • The input is messy human residue
  • The output is stakeholder-readable
Strong line: "Cron is the boring part. The useful part is waking up to a good artifact."

Suggested explanation of heartbeat vs cron

Heartbeat is useful when you want the agent to periodically notice things.
Cron is cleaner when you already know the schedule and just want a durable output.

6) Demo three: Offline communications triage

~9 min

Tagline: Turn exported mail into an action list.

Prep

  • Folder: demo/offline-triage/eml/
  • Seed 6–12 curated .eml files with real-ish asks
  • Output: demo/offline-triage/outputs/email-triage.md

Terminal actions

ls demo/offline-triage/eml
# optionally preview one or two subjects

Prompt

Review these exported .eml files and produce an action-oriented triage report.
Extract likely action items, deadlines, waiting-on items, low-priority messages, and ambiguity notes.
Be careful with uncertainty.
Do not modify source files or send replies.

What to emphasize

  • This is intentional offline triage, not a fake email demo
  • Ambiguity should be surfaced, not hidden
  • The same pattern becomes more powerful when connected later
Strong line: "To keep this safe and reproducible, we’re using exported .eml files today."

Expected output sections

  • Message inventory
  • Action items
  • Deadlines / date mentions
  • Waiting on / follow-up needed
  • Low priority / FYI
  • Ambiguity notes

7) Closing

~3 min

Wrap-up line

Today we stayed local-only on purpose.
The pattern I want you to take away is simple:
unknown inputs become reviewable artifacts,
and those artifacts can be generated on demand, on heartbeat, or on schedule.

Bridge to the future

Connections to real systems are where this gets dramatically more valuable.
But if the local-only version is not already useful, the connected version won’t save it.
Mission control option: if time remains, show a simple page that links to the latest generated artifacts. Otherwise assign it as homework.
